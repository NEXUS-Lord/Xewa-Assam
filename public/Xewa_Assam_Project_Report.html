Project overview

Abstract

Xewa Assam is a web-based local services directory designed to make it easier to find everyday services in Assam. The application groups listings into categories such as tutors and coaching, PGs and rooms, mess and food, repair services, delivery and errands, and other services. Visitors can choose a district, search by name or locality, browse categories, view listing details, and contact a provider by telephone or WhatsApp.

The interface is implemented with React and CSS. Listing and account operations are organised through repository modules. When Supabase credentials are available, the application uses Supabase for authentication and listing data; otherwise, it falls back to local demo data. User-submitted listings are marked pending, and administrative screens support review and management workflows.

The location selector has been expanded to cover all 35 districts listed in the Government of Assam district directory. Existing location identifiers for Nagaon and the Tezpur area are retained; the former Tezpur location is represented under Sonitpur district so its existing listings remain associated with the correct district.

The project focuses on a practical, lightweight discovery experience. It does not claim to provide live verification of every listing or populated service coverage in every district. In the current data set, example listings are concentrated in the original Tezpur and Nagaon areas.

Introduction

1.1 Background

Finding a tutor, room, meal service, repair technician, or delivery provider in a smaller town often depends on personal recommendations and scattered online posts. Information can be difficult to compare, and a useful phone number or location may be buried in an old message.

Xewa (“service” in Assamese) proposes one simple directory where people can browse local providers, review essential details, and reach them directly. The project is centred on discoverability and a familiar mobile-friendly interface rather than a complex booking workflow.

1.2 Problem Statement

Residents, students, and newcomers need a convenient way to locate local services and contact providers. A directory can help organise these details, but it also needs a straightforward way to report inaccurate information and review new submissions.

1.3 Proposed Solution

Xewa provides district selection, category browsing, keyword search, locality filtering, listing detail views, and direct Call and WhatsApp actions. Signed-in contributors can suggest listings, while administrative tools support approval and moderation.

Data Model

The public database schema centers on public.listings, which references public.cities and public.categories, and can optionally reference an owner in public.profiles. Photos, reviews, and reports are separate child records. The site presents the rows in public.cities as districts; the database table itself is still named cities.

Relationships: one city or category can be referenced by many listings; each listing has one city and category, and zero or one owner. Listings can have many photos, reviews, and reports. A review belongs to one listing and one profile; a profile can review a listing only once. A report belongs to one listing and may have no profile after its author is deleted. The schema includes reviews as optional groundwork; the current interface has no full review workflow. profiles.id references Supabase Auth.

7.2 Search and Filtering

Search input is debounced before the listing repository is called. The selected district, category, locality, and sort order are passed as filters. The repository applies equivalent filtering in Supabase mode and local demo mode.

7.3 Contact Actions

Telephone links use a cleaned Indian mobile number with the tel: scheme. WhatsApp links use wa.me with a pre-filled message. Share actions use the browser share API when available and otherwise copy listing details.

7.4 Access and Moderation

Visitors may browse without an account. Contribution and report flows require sign-in and account approval. Supabase migrations define row-level policies so data access is protected by the database, in addition to interface guards.

District data update: the application now presents Assam district names. Migration 0006_assam_districts.sql renames the existing Tezpur location to Sonitpur, adds the other district rows, and preserves the established location identifiers for existing listings.

Interface and Discussion

9.1 Home and Discovery

The home screen places the Xewa identity, district picker, service search, and category browsing at the start of the user journey. The refreshed styling uses a restrained forest-green and warm-neutral palette, softer card borders, clearer spacing, and a calmer hero area.

9.2 Service Results

Each service card presents a photo, verification state when applicable, locality, description, pricing information, rating when supplied, and quick contact controls. The detail view gives more space to the photo gallery and service information.

9.3 Forms and Administration

Modal flows support authentication, listing suggestions, profile actions, reporting, pending approval information, and administration. Their purpose is to keep browsing simple while providing structured steps for contribution and moderation.

9.4 Practical Limitations

  • The district selector expands geographic choice; it does not imply that every district already has listings.
  • Sample content and remote image availability depend on the configured data source and network.
  • Supabase database migrations must be applied to the connected project for new district rows to be available remotely.
  • Listing verification is represented as application metadata and requires an actual review process.

District selection covers the full state, while service data currently represents the original Tezpur and Nagaon locations. The project should be seeded with reviewed local listings before it is presented as a populated statewide directory.

Conclusion and Future Scope

10.1 Conclusion

Xewa Assam demonstrates how a focused web application can organise local service information and help people reach providers directly. Its core experience combines district selection, category navigation, search, listing details, and contact actions with contribution and administration workflows.

The project uses React and CSS for the interface and separates data operations into repository modules. Supabase integration supports hosted data and authentication, while local demo data makes the prototype easier to explore. The updated location selector now includes all 35 districts in Assam and retains the current listing relationships through a database migration.

10.2 Future Scope

  1. Collect and verify more provider listings district by district.
  2. Apply the new database migration to the hosted Supabase project.
  3. Add service-area and map-based discovery after location data is reliable.
  4. Introduce ratings and reviews with moderation.
  5. Provide a full Assamese language option.
  6. Improve listing freshness through provider claims and periodic checks.
  7. Review accessibility and performance on a broader range of devices.

“Xewa aims to make local services easier to find through a clear, district-aware directory and direct ways to contact providers.”
